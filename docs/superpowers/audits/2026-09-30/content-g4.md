# Audit: content-g4 (Grade 4 content)

## 1. Coverage

- Authored questions: all 96 in `src/curriculum/grade4/authored.{oa,nbt,nf,md,g}.ts` (counts per standard listed by the `authored.ts` aggregate: OA 18, NBT 18, NF 27, MD 21, G 12). I solved each one blind first (a dump with keys, misconceptions and explanations hidden), then compared to the key: 96/96 agree with the marked key, exactly one correct option each. I then checked every distractor value against its misconception tag, and every explanation step, common-misconception line and concept summary.
- Templates: all 22 in `templates/` (the task said ~24; there are 22 in `GRADE_4_TEMPLATES`), read line by line. Then sampled 22 templates x 20,000 spread seeds (plus an earlier 1,500 sequential seeds) with an independent checker. It parsed the prompt/promptDetails, recomputed the answer itself, and confirmed: exactly one correct option; correct option equals my computed answer; every distractor differs in VALUE (fractions by cross-multiplication, mixed numbers converted to improper, decimals to thousandths, expanded forms summed, orderings re-sorted); options distinct; no NaN/undefined/negative text; ranges (<=100,000, denominators in {2,3,4,5,6,8,10,12,100}, dividend <= 999, divisor 2..9, etc.); nf7 promptDetails list order equals option order. Zero failures.
- Standards file: compared all 25 codes and text to `docs/sources/nc-standards-1-5.json` and the blueprint band table to `nc-eog-blueprint.json` (OA 14-18, NBT 25-29, NF 30-34, MD+G 23-27): all consistent.
- Study guides: read all 25 (`studyGuides.ts`), checked every worked example, trap, and claim.
- Quizzes: every id resolves; no duplicates; module quizzes contain every authored item of their domain; diagnostic and mock share no items; mock allocation 5/8/10/5+2 matches the blueprint arithmetic.
- Engine: read `questionModel.ts`, `template.ts`, `templateTesting.ts`, `questionSource.ts`, `rng.ts`, `answerChecker.ts`, and how QuizRunner/WeakSpots grade.
- Could NOT check: the current (June 2025 revision) NC DPI 4th-grade unpacking PDF (dpi.nc.gov URLs 404 through WebFetch), so the trapezoid finding rests on the 2017 unpacking; rendered UI (whether a "figure description" is drawn or only shown as text); calculator policy on the real EOG.

- Grade-range limits: NBT within 100,000; 3-digit x 1-digit and 2-digit x 2-digit; dividends <= 3 digits, 1-digit divisors; OA.4 numbers <= 50; NF denominators only from the NC set; NF.4 fractions all < 1; MD.2 larger-to-smaller only; MD.4 line plot uses whole numbers (NC, not Common Core fractions).

One theoretical risk: a saved in-progress session stores the chosen label, so if a template's code changes between deploys, a resumed session's label can point at a different option; not present today.

## 3. Recommendations

1. Add a source-of-truth citation test for definitions that differ between NC and Common Core (trapezoid is the live one). A pinned-fact table with a URL and quote, so tests that "enforce inclusive" cannot silently enforce something the source contradicts.
2. Add a "figure consistency" test for study-guide worked examples that give both angles and sides (triangle inequality plus isosceles implies equal angles), or simply review geometry examples by hand.
3. Add an independent-oracle test per template like the one used here (parse the stem, recompute, compare values not text); the existing `assertTemplateSound` only checks the flagged option equals `answerText`, which both come from the same variable, so a generator computing the wrong answer consistently would pass.
4. Add a lint for "correct option uniquely longest" and for misconception tags whose registry text does not fit (hard to automate; a review checklist is enough).
5. Decide and document whether the diagnostic is blueprint-weighted, and test that the displayed baseline uses the same weighting as the mock.
